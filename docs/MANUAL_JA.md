# Excel Query Trigger Manager — ユーザーマニュアル

**Version 1.0.2**

## 1. 概要

Excel Query Trigger Managerは、Excel WorkbookのPower Query更新を自動または半自動で実行するWindows常駐アプリです。

1つのRuleで以下を設定できます。

- 新しいファイルの追加を監視
- 特定ファイルの更新を監視
- 条件に合うファイル更新を監視
- 指定時刻に実行
- Windowsログオン後に実行
- 手動実行
- 1つまたは複数のWorkbookを順番に更新
- 全Queryまたは特定Queryだけ更新
- 自動Refresh前に実行確認

管理者権限なしでの利用を想定し、Windows PowerShell 5.1とMicrosoft Excelを使用します。

---

## 2. インストールと起動

### インストール

初回利用前に、重要な Excel ファイルを必ずバックアップしてください。Dashboard を
閉じても終了せず、プログラムはタスクトレイに常駐します。新規インストール直後の
初回起動だけは、この動作を確認できるよう Dashboard を前面に表示します。

ZIPを任意の場所に展開し、**`Setup.cmd`** をダブルクリックしてください。
小さなウィンドウが開き、あとは自動で進みます。インストールはこれだけです。

インストール先は `%LOCALAPPDATA%\ExcelQueryTrigger` です。ユーザー単位で
書き込み可能、管理者権限が不要で、OneDrive の同期対象外という理由でこの場所を使います。
あわせて、ダウンロードしたZIP由来のブロック解除、スタートメニューへの登録、
（希望すれば）デスクトップショートカットの作成、サインイン時の自動起動の登録まで行います。

更新するときも同じ `Setup.cmd` を実行してください。ルール・履歴・ログは残ります。
アンインストールも同じウィンドウから行え、ルールを残すかどうかを確認します。

### 起動方法

**スタートメニュー**の項目、または作成した場合はデスクトップのショートカットから
起動してください。どちらもインストール先の `Start-Hidden.vbs` を指しており、
コンソール画面を出さずに起動します。

サインイン時の自動起動には `Start-AtLogon.vbs` が登録されます。中身は同じですが、
「サインインによる起動である」ことをアプリに伝える点だけが異なります。
これによりログオン時の更新確認プロンプトが表示されます。

### 起動しないとき

`tools\Start-WithConsole.cmd` はコンソールを表示したまま起動します。
PowerShell の起動エラーが画面に残るため、原因を確認できます。診断用途のみです。

### Windowsサインイン時の自動起動

Setup の画面で設定できるほか、アプリ内の Settings からも切り替えられます。
`HKCU\...\Run` に1つ値を書くだけで、HKLM やサービスは使いません。

## 4. Triggerの種類

### New file added to folder

条件に合う新しいファイルが追加されたときに実行します。

### Specific file updated

指定した1ファイルが更新されたときに実行します。

### Matching file updated

フォルダ内で条件に合うファイルが更新されたときに実行します。

### Scheduled time

アプリが動作中に、指定曜日・指定時刻になると実行します。

### At Windows logon

Windowsログオン後のアプリ起動を利用します。

### Manual only

自動実行せず、Run Now等からのみ実行します。

## 5. ファイル監視の仕組み

監視にはWindowsの `FileSystemWatcher` を使用します。

流れ：

`Windows file event → 種類/名前条件 → Debounce → File-ready check → Cooldown → 確認/Job Queue`

フォルダ内の全ファイルを毎秒検索する方式ではありません。

### Debounce

1回のファイルコピーでもWindowsから複数イベントが発生することがあります。

Debounceは短時間に連続した同一系統の通知を1回のTriggerにまとめます。

### Cooldown

Rule実行直後に同じRuleが繰り返し発火しないよう、一定時間再実行を抑制します。

### File-ready check

ファイル追加直後はまだコピー途中のことがあります。

必要に応じてファイルが安定してからExcel更新を開始します。

### Monitoring health check

監視機能が生きているか、監視先にアクセスできるかを定期的に確認します。

これはフォルダ全体のスキャンではありません。

## 6. 過去差分は追跡しません

非常に重要な仕様です。

アプリは**監視開始後にWindowsから通知されたファイルイベントだけ**を扱います。

起動時に昨日と今日のフォルダ状態を比較しません。

例：

- 20:00 — アプリ停止・帰宅
- 22:00 — CSV追加
- 翌朝08:30 — アプリ起動・監視開始

22:00に追加されたCSVは、翌朝08:30の起動時にはTriggerになりません。

08:30以降に新しく発生した条件一致イベントから監視対象になります。

## 7. Ask before refresh

重いQueryや、実行タイミングを人間が判断したいRuleでは **Ask before refresh** をONにします。

流れ：

`Trigger検知 → 確認ダイアログ → Refresh now / Skip`

確認中は、そのJob用のExcelはまだ開かれていません。

### Refresh now

通常のJob Queueへ入り、Excel Refreshを開始します。

### Skip

今回のTriggerだけをスキップします。

RuleはEnabledのままで監視も継続します。次回Trigger時には再び確認できます。

帰宅前など、長時間Refreshを今は開始したくない場合に便利です。

### 直近に更新済みのときだけ確認

Add wizardのWorkbook選択画面、またはRule編集画面の **Recent refresh protection** で
**Ask before refreshing if updated within** をONにし、分または時間を指定します。
この項目は対象となる自動TriggerでAdvanced settingsの外に表示されます。ファイル、スケジュール、自動ログオンのTriggerが発火すると、
各対象Workbookをバックグラウンドで確認します。

- ExcelがQuery／Pivotの更新時刻を記録していれば、その時刻を使用
- このアプリが正常に更新した場合は、Query更新完了時刻をWorkbook内の専用プロパティに記録
- Workbookの最終保存時刻はQuery更新時刻として代用しない
- すべて指定時間より古ければ、自動的にJob Queueへ追加
- 1つでも直近なら、または確認できないWorkbookがあれば、再更新するかダイアログで確認

共有ファイルの重複更新を減らす機能であり、PC間の排他ロックではありません。2台が同時に
確認し、どちらもまだ保存していない場合は両方が開始する可能性があります。厳密な排他制御には
共有ロックまたは中央サービスが必要です。明示操作である **Run Now** には適用しません。

自動Triggerまたは手動実行が正常完了すると、Dashboardは対象Workbookの情報を
バックグラウンドですぐ再取得し、**Data updated** を更新します。通常の定期走査を待ちません。
**Data updated** はQuery／更新対象データの更新完了時刻だけを示し、単なる編集・保存時刻は
含みません。Excelにもこのアプリにも更新時刻の記録がなければ **Not recorded** と表示します。

## 8. Excel Action

1つのRuleに複数Workbookを登録でき、設定した順に処理されます。

詳細画面の一覧には、Workbookごとに変更できる内容だけを表示します。対象Workbook、Query範囲、
長時間警告、失敗時の継続可否です。Excelの非表示実行、正常完了後の保存、処理後の終了は固定動作のため、
編集可能な列としては表示しません。

主な設定：

- Workbook path
- All queries / Selected queries
- 長時間警告時間
- Error時の継続
- Save前に対応Connectionの完了を待つ設定
- Macro許可設定

Excel Actionは常に非表示で実行され、正常完了後にWorkbookを保存して専用Excelを閉じます。

## 9. All queries / Selected queries

### All queries

Workbook全体の通常のRefresh対象を更新します。

### Selected queries

特定のPower Queryを選択してRefresh開始対象にできます。

ただしQuery間の依存関係はPower Query側で評価されます。

選択したQueryが上流Queryに依存している場合、必要な上流処理も内部的に評価されることがあります。

結果PopupやログにはQuery名が表示されます。

---

## 10. Refresh中でも他のExcelは使えます

通常は問題なく使用できます。

このアプリはRefresh Job用に**専用のExcelインスタンス**を起動し、普段ユーザーが操作しているExcelセッションとは分けて処理します。

ただし、**アプリが現在更新中の同じWorkbookを手動で開いたり編集したりしないでください。**

また、大きなPower QueryはCPU、メモリ、ディスク、ネットワークを使用するため、他のExcel操作が一時的に重くなることはあります。

## 11. Refresh完了判定と長時間処理

単純に「30秒待ってSave」のような方式ではありません。

対応するExcelのRefresh状態や計算状態を確認し、処理が安定してQuietになったことを確認してから完了と判断します。

### Warn after

Warn afterは強制Timeoutではありません。

時間を超えると：

- Warningをログ
- Current Jobに長時間処理を表示
- Excelは自動終了しない
- Power Queryを自動Cancelしない
- 完了するまで待機

します。

### 個別クエリの選択

**Selected queries** には、そのブックが個別に更新できるものが1行ずつ並びます。
種別（**Power Query** / **Connection**）と、データの出力先が表示されます。

- **Table** — シート上のテーブルに読み込まれている
- **PivotTable** — ピボットテーブルの元になっている
- **Data Model** — ブックのデータモデルに読み込まれている
- **Connection only** — どこにも読み込まれていない。Power Query の補助クエリ
  （サンプル ファイル、パラメーター1、ファイルの変換など）はここに入ります。
  名前ではなく「読み込み先がない」ことで判定するので、言語に依存しません
- **Internal** — Excel 内部の接続（ThisWorkbookDataModel、WorksheetConnection_ など）
- **Unknown** — このブックからは読み込み先を読み取れなかった

既定では **Connection only** と **Internal** 以外をすべて表示します。
**Also show staging, helper and internal items** で残りも表示できます（件数つき）。
すでに選択済みの項目は、どちらの表示でも常に見えます（でないと解除できないため）。
読み込み先が1つも判定できないブックでは、推測せずに全件を **Unknown** として表示します。

クエリを更新すると、それが依存する上流のクエリも評価されるため、隠れている項目を
選ぶ必要はほとんどありません。

表示が実態と合っていない場合は **Copy list** を押してください。各項目の種別・
読み込み先・対応する接続名を含む一覧がクリップボードにコピーされます。

### データソースの確認（Test data sources）

ルールを右クリックして **Test data sources...** を選ぶと、そのルールのブックごと・
接続ごとに、接続先サーバーと到達可否を一覧で確認できます。選択した行の完全な接続文字列も
表示され、**Copy report** でまとめてコピーできます。

この確認はブックのファイルを直接読みます（xlsx は zip で、接続情報は
`xl/connections.xml` にあります）。Excel を一切開かないので、Excel で開けないブックでも
動き、診断そのものが認証ダイアログを呼ぶこともありません。読み取りは Excel が保存を
完了できる形でコピーを取るため、更新中に実行しても保存を妨げません。

分かること:

- サーバー名がネットワーク上に存在しない
- サーバーは応答するが、接続文字列が指定するポートで待ち受けていない
- 「ファイルを開くときに更新する」が設定されている（Refresh 手前でプロンプトが出る原因）
- Power Query の接続である（実際の取得先は M 式の中にあり、ここからは読めない）

分からないこと: 到達できるサーバーの向こう側で、キューブ・テーブル・認証情報が今も
有効かどうか。それはルールを実行し、アクティビティログを見てください。プロバイダーが
出したダイアログは自動で閉じられ、タイトルが記録されます。

### ルール一覧の列

| 列 | 内容 |
|---|---|
| Name | ルール名 |
| Trigger | 何をきっかけに動くか |
| Workbook | 対象ブックのファイル名 |
| **Where** | ブックの置き場所。`Local` / `Network` / `OneDrive` / `SharePoint` / `Shared` |
| Status | 監視状態（平易な表記） |
| **Queries** | 更新対象のクエリ。`All` / `3 chosen` / `Mixed` |
| Last Run | このツールが最後に実行した時刻（`12 minutes ago` 形式） |
| Next Run | 次回の実行予定（Scheduled ルールのみ） |
| Duration | 前回の所要時間。普段の倍以上かかった場合は琥珀色 |
| **Data updated** | **データ自体が最後に更新された時刻** |

行にマウスを乗せると、正確な時刻・更新した人・保存した人・所要時間・共有状態の説明が
まとめて出ます。

#### Where（置き場所）が示すこと

共有ファイルは扱いが変わります。他の人が更新することがあり、こちらが更新したいときに
ロックされていることがあり、同期中に読みに行くこともあります。この列は、そのブックが
そういう性質のものかどうかを示します。

- `Local` — このPCのみ。他の人は触れません
- `Network` — UNC パスまたはネットワークドライブ
- `OneDrive` / `SharePoint` — 同期フォルダー配下
- `Shared` — Excel の「ブックの共有」が有効

#### Data updated が Last Run と違う理由

`Last Run` は**このツールが最後に実行した時刻**です。共有ファイルの場合、他の人が
Excel で開いて更新しているかもしれません。`Data updated` は**誰が更新したかに関係なく、
データ自体が最後に更新された時刻**を示します。

読み取り方は次のとおりです。xlsx は zip なので、Excel を起動せずにファイルを直接読みます。

- `xl/pivotCache/pivotCacheDefinition*.xml` の `refreshedDate` / `refreshedBy`
  — ピボットキャッシュの更新時刻と実行者
- `docProps/custom.xml` の `ExcelQueryTriggerLastQueryRefreshUtc`
  — このアプリが正常に更新したQueryの完了時刻
- `docProps/core.xml` の `dcterms:modified` / `cp:lastModifiedBy`
  — ファイルの保存時刻と保存者（Tooltipの参考情報のみ。`Data updated`には使用しない）
- `xl/revisions/` の有無 — 共有ブックかどうか

**Excel のインスタンスは起動しません。** 読み取りは専用のバックグラウンド処理で行い、
ファイル自身のタイムスタンプ（更新日時とサイズ）でキャッシュするため、変わっていない
ブックは二度と開きません。到達できないネットワーク共有があっても Dashboard が
止まらないようにするためです。

読み取りの間はごく短時間ファイルを開きますが、Excel が保存を完了できる形（削除・
リネームを許可するモード）で開くので、更新中の保存を妨げることはありません。
加えて、**更新ジョブの実行中は、そのブックの読み取り自体を行いません。** Excel が
ブックを保存し終えてから、改めて読み直します。

### 起動時の進捗表示

手動で起動したときは、ルールの読み込み、前回状態の復元、ファイル・フォルダー監視の
登録に加えて、Dashboardが最初に必要とするブック情報の読み取りまで起動ダイアログに表示します。
ダイアログ内のStartup detailsには、監視ルールごとの成功・警告、現在のファイル名、
「何件目／総数」、読み取り成功・失敗件数を表示します。読み取り自体は専用のバックグラウンド処理で
行うため、遅いネットワーク共有があっても画面は応答し続けます。初回読み取りが完了するまで
ダイアログを表示し、すべての対象Workbookが「読取完了」または「利用不可」と判定されるまで
Dashboardとタスクトレイを表示しません。初回情報が揃ってから、操作可能なDashboardを表示します。
Windows サインイン時の自動起動ではSplashを表示せず、Dashboardは通常タスクトレイから開くまで非表示です。

### Trigger Rules の高さ

Trigger Rules タイトル右端の **Show all / Compact** で表示を切り替えます。**Show all** は
ルール件数と利用可能な画面領域から高さを自動計算し、**Compact** は通常の高さに戻します。
表示モードは設定に保存され、次回起動時にも復元されます。この操作では監視ルールや
Excel更新エンジンを再起動しません。

Ruleの行をドラッグすると、一覧内の任意の位置へ移動できます。挿入位置は青いマーカーで表示され、
ドロップ後の順序は `rules.json` に保存されます。再起動後も同じ順序で表示されます。

各列の見出しをクリックすると、その列を基準に昇順で並べ替えます。同じ見出しをもう一度クリックすると
降順に切り替わり、見出しの **▲ / ▼** が方向を示します。文字列は表示内容、**Last Run**、
**Next Run**、**Duration**、**Data updated** は実際の日時・秒数で比較します。列ソートは表示上のみで、
`rules.json` の手動順序は変更しません。ソート中に行をドラッグした場合は、現在表示されている順序を
新しい手動順序として保存し、列ソートを解除します。

### バージョン確認と更新

左下のバージョン番号、または右上の `i` にある **About & updates** タブからAboutを
開けます。GitHub の公開Releaseから最新版を
確認するだけで、認証情報は使用せず、Issueなどへの書き込みも行いません。新しい版のZIPは
ファイル名・内部構成・内部バージョンを確認してからSetupへ引き渡します。

**Settings → Basics → Automatically check for updates** で、1日1回のバックグラウンド確認を
ON/OFFできます。既定はONです。OFFにしてもAboutからの手動確認は利用できます。

### 追加できないブック

クエリも接続もないブックは追加できません。判定は **Excel を使わず**、ファイルを
直接読んで行います。次のいずれかがあれば追加できます。

- `xl/connections.xml` の接続（Power Query を含む）
- `xl/queryTables/` のクエリテーブル
- 外部ソースのピボットキャッシュ（`<cacheSource type="external">`）

`.xlsb` のように判定できない形式は、**警告のうえ追加を許可**します。使えるファイルを
誤って弾く方が損失が大きいためです。

### Excel が使えない環境でのクエリ一覧

クエリ一覧は通常、非表示の Excel でブックを開いて取得します。Excel が入っていない、
または COM 登録が壊れている環境では、**ファイルから直接読む方式に切り替わります**。
この場合、各項目の読み込み先は判定できないため、すべて `Unknown` として全件表示します。

### どのクエリを更新するか（Queries）

ルールを選んで **Queries...** ボタン、または右クリック →
**Choose which queries to refresh...** で開きます。質問は1つだけです。

- **Refresh everything in this workbook** — 通常はこちら
- **Refresh only the queries I choose** — **Choose...** で個別に選択

複数ブックを持つルールでは、先にどのブックかを聞きます。「どのクエリか」はブックに対する
問いであって、ルールに対する問いではないためです。

従来はこの設定が Edit → ルールエディタ → アクション選択 → 更新方法、と3階層下にあり、
見つけられませんでした。

### ファイルの追加（Add a file）

Trigger Rules の **Add** ボタンから、3画面のウィザードで追加します。1画面に質問は1つです。

1. 何をTriggerにするか（6種類すべてから選択）
2. そのTriggerで更新するExcelの一覧と実行順
3. ルール名と全体内容の確認

フォルダー系では監視フォルダー、ファイル種類／独自パターン、含む文字、除外文字を、
特定ファイル更新では監視元ファイルをその場で指定できます。2画面目の **Add workbook...** から、
同じTriggerで更新するExcelを複数追加できます。クエリの選択や更新方法はExcelごとに設定し、
一覧の上から順番に実行されます。**Move up / Move down** で実行順を変更できます。
最後の画面ではルール名と、Trigger・Excel・クエリ範囲の全体を確認します。debounce、cooldown、
Warn after は既定値になります。すべての項目を指定したい場合は、右クリック →
**New rule with all options...** から従来のルールエディタを開いてください。
ルールエディタの機能は何も変わっていません。

Scheduled timeは、PCが起動しており、Windowsへサインインしている間だけ実行されます。
PCの電源が切れている、またはサインアウトしている間に過ぎた実行時刻は、後から再実行されません。

名前だけが異なる完全に同一のルールは登録できません。重複判定では、実際に有効なTrigger設定と、
実行順を含むWorkbook Actions全体を比較します。Workbook、Query範囲、更新オプション、実行順の
いずれかが異なる場合は別ルールとして登録できます。

### 実行中・待機中の見分け方

いま Refresh 中のルールは **Trigger Rules** で緑、その後ろに Job が控えている
ルールは薄い黄色で表示されます。

Refresh 中は **Run Now** ボタンの表示が **Add to Queue** に変わります。Excel の
インスタンスは常に1つだけ動かす方針なので、すぐには開始せず **Pending Jobs** の
末尾に積まれます。

### アクティビティログの読み方

**Show** でレベルを絞ります（Everything / Hide routine detail = DEBUG を除く /
Problems only = 警告とエラー / Errors only）。**for rule** でルールを、
**containing** でルール名・ブック名・メッセージに含まれる文字列を絞り込みます。
**Reset** で3つとも解除します。絞り込みは表示だけを変えるもので、記録は失われず、
ログファイルには常にすべて残ります。

**行をダブルクリック**すると、該当ルールの編集画面が開きます。

### ルール一覧の見方

**Next Run** はScheduledルールの次回実行予定です。他のトリガー種別には予測可能な
次回時刻がないため、空欄になります。

**Duration** は、そのルールの普段の所要時間の2倍以上かかった場合に橙色になります。
比較の内容は行のツールチップに出ます。基準値は直近の完了実行の中央値なので、
3回以上実行されてから表示されます。

### 待機中Jobの並べ替えと取り消し

**Pending Jobs** で行を選び、**Move Up** / **Move Down** / **Remove** を使います。
1行が1つのJobで、複数のブックを含むこともあります。

Remove は確認を求めます。Refreshは行われず、ファイルも変更されず、ルール自体も
そのままです。消えるのは待機中の実行予定だけです。すでに開始されたJobはここからは
消せません。**Cancel Job** を使ってください。

### Cancel Job

本当に停止していると判断した場合は **Cancel Job** を使います。

明示的な確認が必要です。

CancelされたRefreshは通常の成功Save処理には進みません。

#### Cancelが効かない場合

Cancelの判定は、Excelへの呼び出しと呼び出しの「間」で行われます。Excelが呼び出しの中で
停止している間は割り込めないため、**Cancel Jobは「即時停止」ではなく「停止要求」**です。

同期クエリでは `RefreshAll` の呼び出し自体がExcelから戻るまでブロックします。その間、
Cancel要求は受け付けられますが実行されず、経過時間だけが増えていきます。

Cancelを受け付けるのは保存開始前だけです。Current Jobが **Saving** / **Closing** /
**Releasing Excel** の間はボタンが無効になり、Exitも安全上重要な処理の完了を待ちます。

Excelが完全に応答しなくなる原因の大半は、データソースのプロバイダーが独自の接続／認証
ダイアログを出していることです。これはCancelを押したかどうかに関係なく、常時監視して
対処します（後述の「非表示Excelのダイアログ」を参照）。

Cancel Jobを押してもExcelが応答しない場合は、

- 待機中のダイアログを**即座に**閉じます。
- **約12秒後**（ダイアログを閉じても解決しなかった場合はすぐに）、そのExcelプロセスを
  終了するかを確認します。Excel自身のウィンドウハンドルから特定したインスタンスだけで、しかも
  保存前の場合に限ります。ディスク上のファイルは変わりません。

#### 非表示Excelのダイアログ

非表示で自動操作しているExcelがダイアログを出した時点で、そのJobは行き止まりです。
画面に見えず、誰も答えられず、その間Excelはすべての自動化呼び出しを拒否します。
Cancelが届かないのはまさにこれが理由です。

そこでダッシュボードは、ブックを開いている間・クエリを更新している間・ブックを保存して
いる間、ダイアログを監視します。15秒経っても消えないダイアログは閉じ、無言のハングを
通常のエラーに変えます。ダイアログのタイトルはアクティビティログに記録されるので、
何を聞かれていたのか後から分かります。

「ダイアログを閉じる」ことと「Excel プロセスを終了する」ことは別の権限です。
**Saving** 中もダイアログは閉じます（回答待ちの間、Excel はまだ何も書いていません）が、
プロセスの強制終了だけは行いません。ファイルを壊しうる唯一の瞬間だからです。

閉じるのは「本当に回答を待っているウィンドウ」だけです。クリックする対象があり、
プログレスバーを持たないことが条件で、*Downloading* / *Opening* / *Saving* /
*Contacting* のように進行中を示すタイトルは対象外です。ネットワーク共有上のブックを
取得している間、Excel はこうしたウィンドウを表示します。これを閉じると、正常に
動いていた更新が失敗してしまいます。

Excel Actionは非表示で実行されるため、回答待ちのダイアログはDashboardの背後に放置せず、
この安全処理の対象になります。

同じ質問が1つのJob中に3回繰り返された場合は、*ExcelDialogLoop* エラーでJobを停止します。
無人で成功する見込みがなく、接続先か認証情報の更新が必要な状態です。

`appSettings` の `autoDismissExcelDialogs` / `excelDialogGraceSeconds` /
`cancelEscalationSeconds` で調整できます。

デバッグログには、専用Excelから取得したプロセスID、ウィンドウハンドル、開始時刻が記録されます。
強制終了前に開始時刻を再確認するため、再利用されたプロセスIDだけでは終了しません。

#### Refresh前のデータソース確認

クエリに触れる前に、ブック内のすべての外部接続を調べ、サーバー名の名前解決を行います。
名前解決できないサーバーこそがプロバイダーのウィザードを呼び出す原因なので、その時点で
Jobを中止し、接続名とサーバー名をメッセージに残します。名前解決はできるが接続文字列に
明記されたポートが応答しない場合も同じ扱いです。それ以外の不確実なケースは警告を残して
Refreshを続行します。

確認の対象になるのは、接続文字列がネットワーク上のサーバー名を明示している接続だけです。
Power Query の接続は該当しません（接続文字列が `Data Source=$Workbook$` となっており、
実際の取得先は M 式の中にあるため）。これらは「確認対象外」としてスキップし、デバッグログに
記録します。ファイル・UNC・Web ソースも同様です。

Jobを中止するのは「そのホストは存在しない」という明確な応答が2回続いた場合だけです。
名前解決自体が失敗した場合（DNS障害、VPN未接続など）は警告のみを残してRefreshを続行します。

確認そのものを止めたい場合は、`config/rules.json` の `appSettings` で `checkDataSources` を
`false` にするか、個別のExcel Actionに `checkConnections` を `false` で指定してください。

非表示Excelの問題を確認する場合は、**Test data sources**、Current JobのStage、Activity Logを
確認してください。回答待ちのExcelダイアログをアプリが閉じた場合は、そのタイトルがログに残ります。

#### 共有ブックのロック

Refresh開始前に、ブックが別のExcelウィンドウや他のユーザーによって使用中でないか確認します。
使用中ならExcelを起動せず、クエリも更新しません。確認後は専用Excelで書き込み可能として開き、
Refresh、保存、終了までそのブックを開いたままにします。Excelが読み取り専用で開いた場合も、
更新を開始せず終了します。

更新中に別のユーザーが同じブックを開いた場合、通常のファイルサーバーでは読み取り専用になります。
このアプリが保存して閉じるまで、同じブックを手動で編集しないでください。

### Refresh中のExit

Refresh中にExitすると、JobをCancelして終了するか確認されます。

Noを選べばRefreshは継続します。

## 12. Refresh Any Excel File

保存Ruleとは無関係に任意のExcelを一度だけ更新できます。

流れ：

`ファイル選択 → 内容確認 → Macro確認（必要時）→ All/Selected queries → Refresh / Choose Another / Cancel`

ファイル選択直後に即実行しないため、誤選択に対して安全です。

完了後は詳細結果Popupに以下を表示します。

- Workbook
- Status
- Start / Finish
- Elapsed
- Save結果
- Query名
- Message

同じ内容はログにも残ります。

## 13. Macro対応Workbook

MacroはDefaultでBlockします。

`.xlsm` / `.xlsb` を選んだ場合、必要に応じてMacroを許可するか確認できます。

特殊なWorkbookでは `Workbook_Open` VBAを使ってQuery接続、Parameter、Source path等を構築する場合があります。

その場合、MacroをBlockすると正しくRefreshできない可能性があります。

MacroをAllowしてもExcel Trust Centerや会社のセキュリティポリシーを回避するわけではありません。

## 14. Workbook安全性

他のユーザーや自分が同じWorkbookを開いている可能性がある場合、ロックやRead-only状態を確認し、安全に書き込めない場合は無理に上書きしない方向で処理します。

自動Refresh中の同一Workbookは手動操作しないでください。

対応するQuery接続では、同期Refreshのために一時的に設定を変更しても、正常Save前に元の設定へ戻します。

### このアプリの読み取りが保存を妨げることはありません

Excel は既存のブックを保存するとき、隣に一時ファイルを書いてから元のファイルを
置き換えます。そのため、元のファイルを掴んでいるものがあると、保存は最後の一手で
失敗します。Dashboard は **Data updated** / **Where** 列や **Test data sources** の
ためにブックのファイルを自分で読みますが、その読み取りが保存を妨げないように
設計されています。

- Excel が置き換えできるモード（削除・リネームを許可）で開く
- 変更のないブックは二度と開かない
- 更新ジョブの実行中は、メタデータの読み取り自体を開始しない

## 16. 設定と保存場所

設定は3つのタブに分かれており、それぞれの項目に「何をするものか」の説明が付いています。

- **Basics** — Windows と一緒に起動するか、ウィンドウを開くか、タスクバーではなく
  時計の横に常駐するか、1日1回自動で更新確認するか。
- **Notifications** — 時計の横に出る通知。**Tell me when a refresh fails**（失敗時に
  知らせる）だけは残す価値があります。他は慣れると煩わしくなります。
- **Advanced** — 各種の待ち時間、マクロの許可、詳細ログ、設定フォルダーとログ
  フォルダーを開くボタン。既定値のままで問題ない項目です。

**Restore defaults** で3タブすべてを既定値に戻せます。ルールには影響しません。
「サインイン時に起動する」だけは対象外です。これは設定ファイルではなく Windows 側の
登録が実体だからです。

アプリ本体：

`%LOCALAPPDATA%\ExcelQueryTrigger`

Rule、Settings、State、Logの実際の保存先はアプリの **Information & Help** から確認できます。

Configuration schema：**4**

## 17. DPI / Parallels

一般的なWindows Display Scaleや、Parallels等の高DPI仮想環境でもUIが崩れにくい表示方式を採用しています。

必要に応じてDialogをWindowsのWorking Area内に収め、入りきらない場合はスクロール可能にします。

### 拡大表示でも文字がぼやけない理由

本アプリは意図的にDPI非対応（DPI-unaware）です。画面は96 DPI基準の固定座標で組まれており、
ウィンドウ全体をWindowsに拡大させることが、150〜200%表示やRetina仮想環境でもレイアウトを
崩さない唯一確実な方法だからです。その副作用として、Windowsがビットマップを引き伸ばすため
文字がにじみます。

そこで各ランチャーが `__COMPAT_LAYER=GdiScaling` を設定します。ショートカットの互換性設定に
ある「高DPIスケール設定の上書き：システム（拡張）」と同じ仕組みです。ウィンドウの拡大は
Windowsに任せたまま、GDIの文字と線だけを実解像度で描画するため、**レイアウトは一切変わらず
描画だけが鮮明になります**。一部のビットマップ要素は拡大されたままに見えますが、正常です。

無効にしたい場合は `Start-Hidden.vbs` / `Start-AtLogon.vbs` / `Setup.cmd` / `tools\Start-WithConsole.cmd`
の `__COMPAT_LAYER` の行をコメントアウトしてください。すでに利用者や情報システム部門が
設定している値は上書きしません。アプリ本体はこの設定に依存しないため、
`ExcelQueryTrigger.ps1` を直接起動した場合は従来どおりのにじんだ描画になるだけです。

## 18. 推奨運用

- 通常起動は `Start-Hidden.vbs`
- 重いRuleはAsk before refreshをON
- Refresh中の同じWorkbookは開かない
- 本当に止める必要がある場合だけCancel Job
- Manual/One-off Refresh後は結果PopupまたはLogを確認
- アプリ停止中の過去イベントは翌朝自動実行されないことを理解して運用
